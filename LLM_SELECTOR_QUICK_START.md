# Быстрый старт: LLM-селектор статей

## Что нового?

Теперь скрапер **не публикует первую попавшуюся статью**, а:

1. 📊 Собирает заголовки статей со **всех источников**
2. 🤖 Отправляет их в **LLM для анализа**
3. ✨ Выбирает **самую интересную** техническую статью
4. 📤 **Публикует только её**

## Установка за 3 шага

### 1. Убедитесь что есть OpenRouter API ключ

В файле `.env` или `config.env`:
```bash
OPENROUTER_API_KEY=your_key_here
```

### 2. Всё уже настроено!

Файл `main.py` уже использует новый метод по умолчанию.

### 3. Запустите

```bash
python main.py
```

## Что изменилось?

### Было (старый метод):
```
Источник 1 → Берём первую статью → Публикуем → СТОП
Если нет → Источник 2 → Берём первую → Публикуем → СТОП
...
```

### Стало (новый метод):
```
Источник 1 → Собираем заголовки
Источник 2 → Собираем заголовки
Источник 3 → Собираем заголовки
...
         ↓
    LLM анализ
         ↓
Выбор лучшей статьи
         ↓
Публикация только её
```

## Преимущества

✅ **Качество**: Публикуется самая интересная статья, а не первая попавшаяся

✅ **Экономия**: Полный скрапинг только одной статьи вместо нескольких попыток

✅ **Гибкость**: Можно настроить критерии выбора

## Возврат к старому методу

Если нужно вернуться к старому поведению, в `main.py` замените:

```python
# Было:
asyncio.run(run_all_scrapers_with_llm_selection())

# На:
asyncio.run(run_all_scrapers_legacy())
```

## Настройка критериев выбора (опционально)

В `.env` можно изменить промпт для LLM:

```bash
ARTICLE_SELECTION_PROMPT=Твои кастомные критерии выбора статьи...
```

## Логи

Смотрите что происходит:
```bash
tail -f article_selector.log
```

## Проблемы?

1. **"No articles collected"** → Проверьте что источники доступны
2. **LLM ошибка** → Проверьте `OPENROUTER_API_KEY` и баланс
3. **Fallback на первую статью** → Это нормально, если LLM не смог выбрать
